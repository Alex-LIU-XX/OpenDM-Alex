## 1. 模型权重

| 模型 | 路径 | 大小 | 张量精度 | 用途 |
| --- | --- | --- | --- | --- |
| DM05 | `/mnt/cfs/opendm/checkpoints/DM05` | 11.66 GB | BF16 | 通用基座，给 RoboTwin2 / LIBERO 等 SFT 用 |
| **DM05-MEM** | `/mnt/cfs/opendm/checkpoints/DM05-MEM` | 11.66 GB | BF16 | **memory 基座**，RoboDojo SFT 的起点 |
| **DM05-MEM-Robodojo-Sim** | `/mnt/cfs/opendm/checkpoints/DM05-MEM-Robodojo-Sim` | 23.32 GB | **F32** | **榜单模型**，直接用/直接评测 |
| DM05-sdpa-verify | `/mnt/cfs/opendm/checkpoints/DM05-sdpa-verify` | 覆盖层 | — | 只有 `config.json` 是实体，其余 11 个软链到 `../DM05` |

### 校验值（sha256 = HF 上的 LFS oid，已逐一核对通过）

```text
DM05                  b7da77f516ebd0c0c68faed2f0cfe1c68985b7b874e49dda4292d8d286de20dd  11658431136 B
DM05-MEM              cbbdf7b8d874225d49d789390c87720c62ce0332f39a47531a4d1266606ec09a  11658431104 B
DM05-MEM-Robodojo-Sim db5f19ac29bd049ceee542db37263a470c15a6c33a589a446e274c5ac5cbf3ba  23316655136 B
```

> `DM05` 与 `DM05-MEM` 体积几乎相同（差 32 B）但**不是同一份权重**，sha256 不同；别互相替代。

自检命令：

```bash
sha256sum /mnt/cfs/opendm/checkpoints/{DM05,DM05-MEM,DM05-MEM-Robodojo-Sim}/model.safetensors
```

### 两个模型的差异（实测）

| 项 | DM05-MEM | DM05-MEM-Robodojo-Sim |
| --- | --- | --- |
| `model.safetensors` | 11.66 GB，1473 张量，**全 BF16** | 23.32 GB，1473 张量，**全 F32** |
| `config.json` `dtype` | `bfloat16` | `float32` |
| `chunk_size` | 50 | 50 |
| `action_dim` | 32（padding 后；实际动作 14 维） | 32（同上） |
| VLM | `Gemma3ForConditionalGeneration` | `Gemma3ForConditionalGeneration` |
| `norm_stats.json` | 单档 state/action 各 14 维，**带 `control_modes: {joint, eef}`** | 单档 state/action 各 14 维，**无 `control_modes`**，统计量只有 `mean/q01/q99/std` |

> 架构与张量数完全一致，**2 倍体积纯粹是精度差异**（榜单模型存成了 fp32）。按默认 `bf16` 加载会在 load 阶段降精度，显存约 11.7 GB；若真按 fp32 加载需 ~23 GB 显存。

## 2. 官方数据集（RoboDojo-Sim）

| 项 | 值 |
| --- | --- |
| 解压后路径 | `/mnt/cfs/opendm/datasets/robodojo_sim` |
| 仓库软链 | `/root/workspace/opendm/data/robodojo_sim` → 上面的 CFS 路径 |
| 压缩包归档 | `/mnt/cfs/opendm/datasets/_archives_robodojo_sim/robodojo_sim.tar.gz.part-{aa,ab}` |
| 体积 | 解压后 **15 GB**（jsonl 1.8 GB + video 14 GB）；压缩包 14.11 GB（10.74 + 3.37） |
| 规模 | **34 个任务 × 100 episodes = 3400 episodes**；3400 个 `.jsonl`，10200 个 `.mp4` |
| 来源 | HF `Dexmal/robodojo-sim`（经 ModelScope 镜像下载，sha256 与 HF LFS oid 一致） |

### 目录结构

```text
/mnt/cfs/opendm/datasets/robodojo_sim/
├── jsonl/<task>/episode_XXXXXXX.jsonl      # 每帧一行 JSON
└── video/<task>/episode_XXXXXXX/
    ├── cam_head.mp4
    ├── cam_left_wrist.mp4
    └── cam_right_wrist.mp4
```

### 单帧 JSONL 实际格式（cover_blocks 第一帧）

```json
{"images_1":{"type":"video","url":"./cover_blocks/episode_0000000/cam_head.mp4","frame_idx":0},
 "images_2":{"type":"video","url":"./cover_blocks/episode_0000000/cam_left_wrist.mp4","frame_idx":0},
 "images_3":{"type":"video","url":"./cover_blocks/episode_0000000/cam_right_wrist.mp4","frame_idx":0},
 "state":[14 维],"action":[14 维],
 "prompt":"Cover the blocks from left to right, remember their colors, then uncover them in the order: red, green, and blue.",
 "is_robot":true,
 "task_name":"robodojo_cover_blocks"}
```

- `url` 相对注册文件的 `image_dir`（`./data/robodojo_sim/video`）解析，所以 `url` 自带任务名一层。
- `state` / `action` 都是 **14 维绝对关节**（6 关节 + 夹爪，×2 臂）。
- 数据集**不带** `index_cache.json`，首次运行时由 OpenDM 扫描生成（写到 `jsonl/<task>/` 下）。

### 与注册文件的对应关系

`opendm/dataset/robodojo.py` 注册名 `robodojo_sim_cover_blocks`（前缀 `robodojo` + 键 `sim_cover_blocks`）：

```python
"jsonl_dir": "./data/robodojo_sim/jsonl/cover_blocks",
"image_dir": "./data/robodojo_sim/video",
"image_keys": ["images_1", "images_2", "images_3"],
"image_prompts": ["Head", "Left wrist", "Right wrist"],
"robot_type": RobotType.ALOHA,
"state_desc": ROBOT_STATE_DESCS[RobotType.ALOHA],   # 14 维关节
"fps": 25, "speed": "0.5"
```

**注意**：注册里只指向 `cover_blocks` 单任务。要训全部 34 个任务（generalist），加一个参数即可（`url` 自带任务目录，`image_dir` 不用改）：

```bash
--data-config.jsonl-dir ./data/robodojo_sim/jsonl
```

## 3. 下载通道（本机实测）

| 通道 | 实测速度 | 结论 |
| --- | --- | --- |
| `huggingface.co` | 超时，**完全不通** | 不能用 |
| `hf-mirror.com` | 单连接 **51 KB/s**；8 线程并行 Range 合计 **~3.5 MB/s** | 太慢，仅作 sha256 查询用 |
| **`modelscope.cn`** | 单流 **17–25 MB/s** | ✅ **用这个** |

### 复现下载的命令（脚本原在 `/tmp`，容器重建会丢，故内联）

数据集（14.11 GB，实际约 12 分钟）：

```bash
DEST=/mnt/cfs/opendm/datasets/robodojo_sim && mkdir -p $DEST
# 列文件
curl -s "https://modelscope.cn/api/v1/datasets/Dexmal/robodojo-sim/repo/tree?Revision=master&Root="
# 逐个下载（-C - 支持断点续传；文件清单以 curl 输出为准）
for f in .gitattributes dataset_infos.json README.md \
         robodojo_sim.tar.gz.part-aa robodojo_sim.tar.gz.part-ab; do
  curl -L -C - --retry 8 --retry-delay 5 -o "$DEST/$f" \
    "https://modelscope.cn/api/v1/datasets/Dexmal/robodojo-sim/repo?Revision=master&FilePath=$f"
done
```

模型权重（注意路径是 `models` 不是 `datasets`）：

```bash
DEST=/mnt/cfs/opendm/checkpoints/DM05-MEM && mkdir -p $DEST
curl -s "https://modelscope.cn/api/v1/models/Dexmal/DM05-MEM/repo/files?Revision=master&Root="
for f in model.safetensors config.json norm_stats.json tokenizer.json tokenizer_config.json \
         chat_template.jinja generation_config.json configuration.json processor_config.json \
         README.md .gitattributes; do
  curl -L -C - --retry 8 --retry-delay 5 -o "$DEST/$f" \
    "https://modelscope.cn/api/v1/models/Dexmal/DM05-MEM/repo?Revision=master&FilePath=$f"
done
```

解压（两个分卷是**同一个 gz 流切开**的，必须按序 cat 后整体解压）：

```bash
cd /mnt/cfs/opendm/datasets
cat robodojo_sim/robodojo_sim.tar.gz.part-aa robodojo_sim/robodojo_sim.tar.gz.part-ab \
  | tar -xzf - -C .        # 得到 ./robodojo_sim/{jsonl,video}
```

> 归档分卷 sha256（= HF LFS oid，已核对）：
> `part-aa 27bb75ffe96ffe470aa6e0fae6502dfdeb1f4c9acbad37ecc56a767206f07413`（10737 MB）
> `part-ab 076578c08229944a38a9a74ccb4aa66085365d46bdae3f10d71a3f98fdedc4f3`（3373 MB）

## 4. 榜单模型官方口径（来自 HF/ModelScope 模型卡）

- 结构：**Gemma 3 4B VLM + 680M Action Expert**
- 机型：**ARX X5 双臂**
- 输入：head + left-wrist + right-wrist 三路 RGB，外加**最多 20 帧 head 历史（1 FPS 采样）**；episode 开头的空槽**左侧 padding**
- 输出：**14 维绝对关节位置，chunk 长度 50**；RoboDojo 评测适配器**只执行每个 chunk 的前 25 步**
- 必须使用 checkpoint 自带的 `norm_stats.json`；相机顺序、动作模式、history 策略都不能改
- 评测走 **RoboDojo 官方流程 + XPolicyLab**（[PR #101](https://github.com/XPolicyLab/XPolicyLab/pull/101)，已合并则用 main），**不是** OpenDM 的 HTTP `/v1/infer`

榜单成绩（2026-08-24 快照）：

| Metric | Gen-Std | Gen-Rand | Precision | Long-Horizon | Memory | Open | Average |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Score | 23.49 | 8.06 | 24.82 | 33.70 | **47.74** | 2.43 | **24.90** |
| Success Rate (%) | 18.00 | 4.00 | 16.75 | 19.50 | **47.44** | 2.08 | **19.34** |

## 5. 已知坑

1. **flash-attn 没装**（`/root/miniconda3/envs/opendm` 里 `is_flash_attention_2_available() == False`），而 RoboDojo 入口默认 `vision_attn_implementation="flash_attention_2"` → 直接起会 `ImportError`。**必须显式加 `--model-config.vision-attn-implementation sdpa`**（`.smoke/scripts/run_inference_e2e.sh` 里也是这么处理的）。`flex_attention` 可用（torch 2.11）。
2. **`chunk_size` 25 vs 50**：仓库 `playground/dm05_mem_sft_robodojo_cover_blocks.py` 默认 **25**，那是给"单任务 cover_blocks 参考训练"用的；**榜单权重原生是 50**，用它推理/评测时要显式传 50。
3. **本地盘只剩 ~40 GB**：数据集、权重、`--trainer-config.output-dir` 都放 CFS。`data/robodojo_sim` 已经是软链，仓库内相对路径可照用。
4. **文档里的 `./checkpoints/DM05-MEM` 不存在**：本机权重在 CFS，`--model-config.model-name-or-path` 要换成绝对路径。
5. **官方 norm_stats 是现成的**：不用另外下载，就在 `/mnt/cfs/opendm/checkpoints/DM05-MEM-Robodojo-Sim/norm_stats.json`，`--data-config.norm-stats-root` 指向该目录即可（`norm_stats_path()` 会取 `<root>/norm_stats.json`）。
6. **单卡时不会开 FSDP**：`trainer.py` 里只有 `fsdp1 and world_size > 1` 才启用，1×A100 是把整个模型塞进 80 GB。官方命令默认 8 卡 × batch 4 = 全局 32；单卡跑要么接受 batch 4，要么用 `--trainer-config.gradient-accumulation-steps 8` 补回等效 batch。
7. **别把 EE 数据和官方数据搞混**：`/mnt/cfs/data/robodojo/RoboDojo_ee_*` 是 **16 维 EE**（pos+四元数+夹爪 ×2），官方数据集是 **14 维关节**，两者动作空间不同、norm_stats 不通用。有意思的是 episode 是对得上的：`cover_blocks`（官方，100 eps）与 `RoboDojo_ee_cover_v30`（本地，100 eps）**都是 54396 帧**，只是动作表示不同。

## 6. 常用命令

均以本机路径为准（1×A100）。

### 6.1 榜单模型起推理服务（HTTP 自测用）

```bash
cd /root/workspace/opendm
script/dm05_launcher.sh \
  --exp playground/dm05_mem_sft_robodojo_cover_blocks.py \
  --task inference \
  --model-config.model-name-or-path /mnt/cfs/opendm/checkpoints/DM05-MEM-Robodojo-Sim \
  --model-config.chunk-size 50 \
  --model-config.vision-attn-implementation sdpa \
  --inference-config.port 7891
```

### 6.2 cover_blocks 单任务 SFT（官方参考流程）

```bash
cd /root/workspace/opendm
script/dm05_launcher.sh \
  --exp playground/dm05_mem_sft_robodojo_cover_blocks.py \
  --task train \
  --nproc_per_node 1 \
  --data-config.dataset-name robodojo_sim_cover_blocks \
  --data-config.norm-stats-root /mnt/cfs/opendm/checkpoints/DM05-MEM-Robodojo-Sim \
  --model-config.model-name-or-path /mnt/cfs/opendm/checkpoints/DM05-MEM \
  --model-config.vision-attn-implementation sdpa \
  --trainer-config.num-train-steps 30000 \
  --trainer-config.output-dir /mnt/cfs/opendm/runs/dm05_mem_sft_robodojo_cover_blocks
```

### 6.3 全部 34 任务（generalist 方向）

在上面基础上追加：

```bash
  --data-config.jsonl-dir ./data/robodojo_sim/jsonl
```

### 6.4 评测

按官方文档接 XPolicyLab（`policy/OpenDM/deploy.yml` 需与训练配置对齐）：

```yaml

action_steps: 25
history_enabled: true
history_slots: 20
history_fps: 1.0
runtime_fps: 25.0
model_action_mode: absolute
robot_type: Aloha
speed: "0.5"
model_max_length: 1536
```
