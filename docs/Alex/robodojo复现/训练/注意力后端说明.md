## 0. 速查（TL;DR）

| | **SDPA** | **FA2** |
| --- | --- | --- |
| 全称 | `torch.nn.functional.scaled_dot_product_attention` | FlashAttention-2 |
| 是什么 | PyTorch **内置的算子接口 + 后端调度器** | Dao-AILab 开源的**一套具体 CUDA 内核**（`flash-attn` 包） |
| 谁提供 | PyTorch 官方，2.0 起内置 | 第三方，**必须按 torch/CUDA 版本现场编译** |
| 装不装 | 有 torch 就有 | 不装就没有 |
| 类比 | USB 接口 + 自动挑驱动 | 某一块具体的 USB 控制器芯片 |

**本文最重要的一句话**：本机实测，**默认 SDPA 调用的就是 PyTorch 自带的 cutlass flash 内核**（`pytorch_flash::flash_fwd_kernel`）。所以"用 SDPA"≠"没用 flash 类内核"，**"SDPA vs FA2"本质是同一个算法的两个实现之比**——实测两者打平（第 4 节）。

## 1. 先看注意力在算什么

$$\text{attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

序列长 $S$、每头维度 $d$。**朴素实现**要把 $S\times S$ 的分数矩阵显式算出来再 softmax：

- **显存 $O(S^2)$**：$S=11776$、8 头、bf16 时，单层单样本的分数矩阵约 $8\times11776^2\times2\text{B}\approx2.2$ GB，反向还要再存一份；
- **算力吃不满**：这个矩阵反复读写 HBM，属 memory-bound，Tensor Core 大量时间在等数据。

**FlashAttention（2022, Dao et al.）的核心**就两条：分块（tiling）——把 $QK^\top$ 切块放进 SRAM 算完即弃，$S\times S$ 矩阵**从不写回显存**，显存降到 $O(S)$；反向不保存中间量，用**重算**换显存。**FA2（2023）**在此基础上改进并行划分、减少非矩阵乘开销。后来 PyTorch 把同类内核**内置**进了 SDPA。

## 2. SDPA：PyTorch 的统一入口（调度器）

```python
import torch.nn.functional as F
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

同一行调用，PyTorch 按 **dtype / 设备 / 形状 / mask** 自动在多个后端里挑一个：

| SDPBackend 成员（本机 `torch 2.11` 实测枚举） | 说明 |
| --- | --- |
| `FLASH_ATTENTION` | CUTLASS 实现的 flash 内核，**PyTorch 自带** |
| `EFFICIENT_ATTENTION` | xFormers 血统的 memory-efficient 内核 |
| `CUDNN_ATTENTION` | cuDNN 的 fused attention（新版 torch + 新卡） |
| `MATH` | 朴素实现（sgemm + softmax），兜底与数值基准 |
| `OVERRIDEABLE` / `ERROR` | 调度用，不是真后端 |

本机四个后端开关全为 `True`（`flash_sdp_enabled` / `mem_efficient_sdp_enabled` / `math_sdp_enabled` / `cudnn_sdp_enabled`）。

### 2.1 实测：强制指定后端时，真正跑的是哪个内核

形状 `(B=4, H=8, S=1536, D=256)`、bf16、causal，用 `sdpa_kernel(...)` 强制 + `torch.profiler` 抓内核名：

| 强制后端 | 实测内核（截断） | 结果 |
| --- | --- | --- |
| `FLASH_ATTENTION` | `pytorch_flash::flash_fwd_kernel<Flash_fwd_kernel_traits<256,128,64,8,...,cutlass::bfloat16_t...` | ✅ |
| `EFFICIENT_ATTENTION` | `fmha_cutlassF_bf16_aligned_32x128_gmem_sm80(PyTorchMemEffAttention::AttentionKernel<...>)` | ✅ |
| `CUDNN_ATTENTION` | — | ❌ `RuntimeError: No available kernel`，警告明说 **`head_dim should be no more than 128`** |
| `MATH` | `ampere_sgemm_128x128_tn` + `softmax_warp_forward` | ✅（作数值基准） |

数值一致性：bf16 下三个可用后端与 `MATH` 的**最大绝对误差 0.0078**（该形状下），即 bf16 的舍入量级，说明它们算的是同一个东西。误差随形状变化——第 8 节脚本换用 `(1,8,512,128)` 时读到 0.0156，仍是同一量级。

> ⚠️ **注意 cuDNN 后端在 `head_dim=256` 下直接不可用** —— 而 Gemma3 的 LLM 正是 `head_dim=256`。所以"能不能用某个后端"是**跟形状绑定**的，不是一个开关的事。

### 2.2 实测：**不指定**后端时，默认挑的是谁

同样用 profiler 探针，四种形状全部落到同一个内核：

| 形状 (B,H,S,D) | 默认派发到的内核 |
| --- | --- |
| (4,8,1536,256) | `pytorch_flash::flash_fwd_kernel` |
| (1,8,1536,256) | `pytorch_flash::flash_fwd_kernel` |
| (4,8,1536,128) | `pytorch_flash::flash_fwd_kernel` |
| (4,8,11776,256) | `pytorch_flash::flash_fwd_kernel` |

**这就是"SDPA 已经很快"的物证**：默认路径已经是 flash 类内核，不是朴素实现。

## 3. FA2：FlashAttention-2 是什么

- **来历**：FlashAttention 论文（Dao et al., 2022）的官方工程实现，v2 是 2023 年的改进版；包名 `flash-attn`，import 名 `flash_attn`。
- **和 SDPA 的关系**：**不是对立的两个东西**。SDPA 是接口/调度器，FA2 是其中一个具体实现（另一个来源）。在 PyTorch 2.0 之前 SDPA 不存在，想要 flash 类内核只能装它——很多"必须装 flash-attn"的经验是那个年代留下的。
- **门槛**：
  - 要**现场编译**，且 ABI 必须和 torch/CUDA 对上（本机编了 33 分钟，见 `冒烟测试与训练实操.md` 4.5）；
  - 形状/类型有约束：fp16/bf16、`head_dim ≤ 256`、最后一维连续、**不支持任意 attention bias / 复杂 mask**；
  - 新算子、新卡要等上游适配。
- **在本仓库里的落地范围**：`is_flash_attention_2_available()` 判断它在不在；checkpoint 的 `config.json` 把 **vision** 后端钉成 `flash_attention_2`，所以不装它连模型都构造不出来（构造期就 `ImportError`）。

## 4. 实测：FA2 到底比 SDPA 快吗？

### 4.1 内核级微基准（bf16 + causal + fwd&bwd，A100-80G）

| 形状 (B,H,S,D) | FA2 ms | SDPA ms | SDPA/FA2 |
| --- | ---: | ---: | ---: |
| (1,8,1536,256) | 0.83 | 0.73 | 1.14×（FA2 更慢） |
| (4,8,1536,256) | 2.11 | 2.11 | 1.00× |
| (4,8,5888,256) | 18.25 | 15.52 | 1.18×（FA2 更慢） |
| (4,8,11776,256) | 53.83 | 54.33 | 1.01× |
| (4,8,1536,128) | 1.06 | 1.07 | 1.01× |
| (4,8,4096,128) | 4.40 | 4.51 | 1.02× |
| (4,32,4096,128) | 13.73 | 14.17 | 1.03× |
| (1,8,11776,128) | 6.20 | 6.39 | 1.03× |

即使到 11776 token 的长序列，FA2 也只有 1–3% 优势；**`head_dim=256`（Gemma3 的形状）下反而更慢**。

### 4.2 端到端 A/B（官方权重全参 SFT，3 步，只换 vision 后端）

| 配置 | 峰值显存 | 稳态步时 |
| --- | ---: | --- |
| vision=FA2 / batch 1 | 59058 MiB | ~2 s |
| vision=SDPA / batch 1 | 59058 MiB | ~2 s |
| vision=FA2 / batch 4 | 69934 MiB | ~5 s |
| vision=SDPA / batch 4 | 69936 MiB | ~4–5 s |

**打平。**

### 4.3 为什么打平（三个叠加原因）

1. **算法相同**：本机 SDPA 默认派发的就是 cutlass flash 内核（2.2 节实测）——两个实现比同一个算法；
2. **FA2 在这个入口只作用于视觉塔**：3 图 × 256 token = **768 token**，注意力开销本就可忽略；计算大头 LLM 默认走 `flex_attention`，其值域里**没有 `flash_attention_2`**；
3. **`head_dim=256` 不是 FA2 的甜点形状**（它优化最好的是 64/128）。

**结论：装 flash-attn 的收益是"与官方默认配置对齐、不必再造 sdpa 视图"，而不是提速。** 真提速要靠多卡 FSDP、更大的有效 batch，或削减数据侧开销（图像/视频解码、dataloader）。

## 5. 怎么确认"现在到底走了哪个后端"

不要靠猜，用 profiler 抓内核名（本机已验证可用）：

```python
import torch, torch.nn.functional as F, re
from torch.profiler import profile, ProfilerActivity

q = torch.randn(4, 8, 1536, 256, dtype=torch.bfloat16, device="cuda")
k, v = torch.randn_like(q), torch.randn_like(q)
for _ in range(3):                                   # warmup
    F.scaled_dot_product_attention(q, k, v, is_causal=True)
torch.cuda.synchronize()
with profile(activities=[ProfilerActivity.CUDA]) as prof:
    F.scaled_dot_product_attention(q, k, v, is_causal=True)
    torch.cuda.synchronize()
for e in prof.key_averages():
    if re.search(r"flash|fmha|cutlass|softmax|sgemm", e.key, re.I):
        print(e.key[:110])
```

判据（本机实测的名称）：

| 看到的字样 | 说明 |
| --- | --- |
| `pytorch_flash::flash_fwd_kernel` | PyTorch 自带的 cutlass flash 内核（**默认走的就是这条**） |
| `fmha_cutlassF_..._sm80` | memory-efficient 内核 |
| `sgemm` + `softmax_warp_forward` | 朴素 MATH 路径 |
| `flash_fwd_kernel` 但库名是 `flash_attn` 相关 | 第三方 FA2 内核 |

想强制某个后端做对照，用上下文管理器：

```python
from torch.nn.attention import SDPBackend, sdpa_kernel
with sdpa_kernel(SDPBackend.FLASH_ATTENTION):        # 或 EFFICIENT_ATTENTION / CUDNN_ATTENTION / MATH
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

## 6. 本仓库的开关与选型建议

### 6.1 三个开关（RoboDojo 入口的实际值域）

| 字段 | 允许值 | 本入口默认 | 能否用 FA2 |
| --- | --- | --- | --- |
| `--model-config.llm-attn-implementation` | `auto / eager / sdpa / flex_attention` | `flex_attention` | ❌ 值域里没有 |
| `--model-config.vision-attn-implementation` | `auto / eager / sdpa / flash_attention_2` | `flash_attention_2` | ✅ 唯一能落地处 |
| `--model-config.action-attn-implementation` | `auto / eager / sdpa / flex_attention` | `sdpa` | ❌ 值域里没有 |

传了不在值域里的值会 `Invalid choice ... Expected one of (...)` + **exit 2 秒退**，看起来很像崩溃，先查参数值域（详见 `冒烟测试与训练实操.md` 4.3）。

### 6.2 `flex_attention` 是什么

第三个选项，容易和 FA2 混淆：PyTorch 2.5+ 的**可编程 fused attention**（支持自定义 mask、score 修改等），torch 2.11 可用、A100 支持（本机 `from torch.nn.attention.flex_attention import flex_attention` 导入正常）。它不是 FA2 的替代，而是"更灵活但同类"的融合实现；本入口 LLM 默认就用它。

### 6.3 选型建议

| 场景 | 建议 |
| --- | --- |
| 本入口训练/推理（torch 2.11 + A100） | 默认即可：LLM `flex_attention`、vision `flash_attention_2`（需装 FA2）或 `sdpa`（不装也行，但要 sdpa 视图绕开 config 钉死） |
| 想省事/换机器 | 不装 FA2、用 `sdpa` + sdpa 视图，性能实测无差 |
| 想少一层配置差异 | 装 FA2，官方默认原样跑（本机已装好） |
| 追求吞吐 | **别在后端上抠**：加卡（FSDP）、加大有效 batch、削数据侧开销才是杠杆（见 `冒烟测试与训练实操.md` 第 6 节时间预算） |

## 7. 四个常见误解

| 误解 | 实际 |
| --- | --- |
| "用了 SDPA 就是没用 flash 类内核" | ❌ 本机默认 SDPA 派发的就是 `pytorch_flash::flash_fwd_kernel` |
| "装了 FA2 训练一定更快" | ❌ 本机实测打平；`head_dim=256` 时甚至略慢 |
| "FA2 哪里都能用" | ❌ 本入口只允许 vision 用；LLM/action 的 Literal 值域里没有它 |
| "报 `FlashAttention2 has been toggled on, but ... not installed` 是代码 bug" | ❌ 只是没装包，且报错发生在**模型构造期**，命令行传 `sdpa` 来不及生效（要用 sdpa 视图或装包） |

      torch.backends.cuda.flash_sdp_enabled(), torch.backends.cuda.mem_efficient_sdp_enabled(),

## 9. 一句话总结

> **SDPA 是接口，FA2 是实现；本机的 SDPA 默认已经在用 flash 类内核，所以两者打平。**
> 装 flash-attn 的意义是**配置与官方默认对齐**，不是性能；想快，去加卡、加有效 batch、削数据侧开销。
