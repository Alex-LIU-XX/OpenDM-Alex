# RoboDojo 数据集对比分析：OpenDM 官方版 vs Benchmark 官方版

- 记录时间：2026-09-30 14:07 (CST)
- 对比对象：
  - **A｜OpenDM 官方训练数据**（HF `Dexmal/robodojo-sim`）→ `/mnt/cfs/opendm/datasets/robodojo_sim`，仓库内软链 `data/robodojo_sim`
  - **B｜RoboDojo Benchmark 官方数据**（ModelScope `RoboDojo-Benchmark/RoboDojo` 的 `RoboDojo_ee_lerobot_v30_video`）→ `/root/data/robodojo/RoboDojo_ee_lerobot_v30_video`（`/root/data` 是 `/mnt/cfs/data` 的软链）
- 结论一句话：**这不是两套数据，而是同一批 rollout 的两种表示**。帧级 1:1 对应；真正的差别在「动作空间（关节 14 维 vs EE 16 维）＋任务集合（34 vs 35）＋封装格式（自定义 jsonl vs LeRobot v3.0）＋视频编码（h264 0.4 Mbps vs av1 5.3 Mbps）」。

---

## 0. 速览

| 维度 | A｜OpenDM `robodojo-sim` | B｜Benchmark `RoboDojo_ee_lerobot_v30_video` |
| --- | --- | --- |
| state / action | **14 维关节**：每臂 6 关节 + 夹爪（弧度、0–1） | **16 维 EE**：每臂 `xyz + 四元数(w,x,y,z) + 夹爪` |
| 动作语义 | 绝对关节目标；`action[t] == state[t+1]` | 绝对 EE 位姿；`action[t] ≈ state[t+1]`（max diff 1.2e-4） |
| 任务 / episodes / 帧数 | 34 / 3,400 / **1,793,999** | 35 / 3,500 / **1,859,602** |
| 与对方的关系 | = B 去掉 letters 任务（34/34 任务帧数逐一相等） | = A + `Arrange the letters to spell "RoboDojo"`（100 eps / 65,603 帧） |
| 存储格式 | 自定义 JSONL（每帧一行）+ 每集 3 个独立 mp4 | LeRobot **v3.0**：parquet + 分片 mp4 + `meta/` |
| 视频编码 / 码率 | h264 / **0.40 Mbps** | av1 / **5.26 Mbps**（近无损） |
| 体积 | **15.8 GB**（jsonl 1.8 + video 14） | **112 GB**（video 112 + data 233 M + meta 39 M） |
| 相机键 | `images_1/2/3` = Head / Left wrist / Right wrist | `observation.images.cam_high` / `cam_left_wrist` / `cam_right_wrist` |
| 分辨率 / 帧率 | 640×480 @ 25 fps | 640×480 @ 25 fps |
| robot_type | ALOHA（OpenDM 注册值） | `unified_robot` |
| episode 编号 | 每任务 0–99 | 全局编号（如 cover_blocks = 300–399） |
| 语言标注 | 帧内 `prompt` 字段（与 B 的任务句逐字相同） | `meta/tasks.parquet` + 逐集 `tasks` |
| 附带统计 | 无（首次运行自建 `index_cache.json`） | `stats.json`、`stats_gr00t*.json`、`steps_data_index*.pkl`、逐集 stats |

## 1. 同源证据（6 条硬证据）

| # | 检验 | 结果 |
| --- | --- | --- |
| 1 | **逐任务帧数** | 34/34 任务**完全相等**（每任务 100 eps） |
| 2 | **逐集长度** | 抽样 7 个任务 × 100 集：逐一相等，`max|diff| = 0` |
| 3 | **总帧数核对** | B 全量 1,859,602 − letters 65,603 = **1,793,999** = A 全量 ✅ |
| 4 | **同帧画面** | cover_blocks ep0 f50：B(av1) vs A(h264) 像素相关系数 **0.998**，平均绝对差 2/255（纯重编码差异） |
| 5 | **夹爪数值** | f50 左夹爪两侧都精确等于 **0.5453** |
| 6 | **时序语义** | 两侧均满足 `action[t] ≈ state[t+1]`，均为**绝对**目标位姿（B 的 `modality.json` 明示 `absolute: true`） |

> 结论：**A 与 B 是同一批仿真 rollout 的两次导出**，只是动作/状态表示与打包方式不同。

## 2. A｜OpenDM 官方版（`robodojo-sim`）

### 2.1 目录结构

```text
/mnt/cfs/opendm/datasets/robodojo_sim/          # 仓库软链 data/robodojo_sim
├── jsonl/<task>/episode_XXXXXXX.jsonl          # 3400 个，共 1.8 GB
└── video/<task>/episode_XXXXXXX/
    ├── cam_head.mp4        # h264, 640×480@25fps, ~0.4 Mbps
    ├── cam_left_wrist.mp4
    └── cam_right_wrist.mp4                     # 10200 个 mp4，共 14 GB
```

### 2.2 单帧格式（实际样例）

```json
{"images_1":{"type":"video","url":"./cover_blocks/episode_0000000/cam_head.mp4","frame_idx":0},
 "images_2":{"type":"video","url":"./cover_blocks/episode_0000000/cam_left_wrist.mp4","frame_idx":0},
 "images_3":{"type":"video","url":"./cover_blocks/episode_0000000/cam_right_wrist.mp4","frame_idx":0},
 "state":[14 维],"action":[14 维],
 "prompt":"Cover the blocks from left to right, remember their colors, then uncover them in the order: red, green, and blue.",
 "is_robot":true,"task_name":"robodojo_cover_blocks"}
```

- `url` 相对注册的 `image_dir`（`./data/robodojo_sim/video`）解析，自带任务名一层。
- 首帧 `state` 约等于全 0、夹爪 1.0（复位姿）；`action[t]` 与 `state[t+1]` 逐元素相等（实测 f0 的 action == f1 的 state）。

### 2.3 语义与注册

| 项 | 值 |
| --- | --- |
| 动作空间 | **14 维绝对关节** = 每臂 6 关节（弧度）+ 1 夹爪（0–1），×2 臂 |
| 注册文件 | `opendm/dataset/robodojo.py`，注册名 `robodojo_sim_cover_blocks`（前缀 `robodojo` + 键 `sim_cover_blocks`） |
| 相机 | `image_keys = [images_1, images_2, images_3]`，`image_prompts = [Head, Left wrist, Right wrist]` |
| 机型 / fps / speed | `RobotType.ALOHA` / 25 / `"0.5"` |
| 历史帧 | 训练入口从主视角 `images_1` 按 1 FPS 回看 20 帧，JSONL 不带 `history_images` |
| 索引缓存 | 数据集**不带** `index_cache.json`，首次运行由 `JsonlDataset` 扫描生成（cover_blocks = 100 文件 / **54,396 帧**） |
| 任务覆盖 | 注册文件只指向 `cover_blocks`；训全部 34 任务需显式传 `--data-config.jsonl-dir ./data/robodojo_sim/jsonl` |

## 3. B｜Benchmark 官方版（LeRobot v3.0）

### 3.1 目录结构

```text
RoboDojo_ee_lerobot_v30_video/                  # 112 GB，来源 ModelScope，master 修订
├── meta/
│   ├── info.json                 # 35 任务 / 3500 eps / 1,859,602 帧 / fps 25 / chunks_size 1000
│   ├── modality.json             # ★ 各段语义切片（position / quaternion / gripper，absolute）
│   ├── stats.json                # 全局逐维统计（min/max/mean/std/q01..q99）
│   ├── stats_gr00t*.json         # GR00T 口径统计
│   ├── steps_data_index*.pkl     # 预建步索引（17.7 MB）
│   ├── tasks.parquet             # 35 条任务句 ↔ task_index
│   └── episodes/chunk-000/file-000.parquet    # 3500 行逐集元数据（length / 视频分片 / from-to 时间戳 / 逐集 stats）
├── data/chunk-000/file-*.parquet # 233 MB，state/action(16) + timestamp/frame_index/episode_index/task_index
└── videos/observation.images.{cam_high,cam_left_wrist,cam_right_wrist}/chunk-000/file-*.mp4
                                  # av1, 640×480@25fps, ~5.26 Mbps（cam_high 单路 48 GB）
```

### 3.2 单帧语义（`meta/info.json` + `modality.json`）

```text
observation.state / action = 16 维：
  [0:3]   end_left_position     xyz
  [3:7]   end_left_rotation     quaternion (w, x, y, z)
  [7:8]   left_gripper
  [8:11]  end_right_position    xyz
  [11:15] end_right_rotation    quaternion
  [15:16] right_gripper
```

- `modality.json` 对 state/action 都标注 `absolute: true`、`rotation_type: "quaternion"`。
- 实测覆盖范围（cover_blocks ep0）：四元数模长恒为 1.0；夹爪 0.545–1.0；`action[t]` 与 `state[t+1]` 最大绝对差 1.2e-4。
- 帧率由 `timestamp` 步长 0.04 s 印证为 25 fps。

## 4. 逐项差异汇总

| 维度 | A｜OpenDM | B｜Benchmark | 影响 |
| --- | --- | --- | --- |
| 动作空间 | 14 维关节（弧度 + 夹爪） | 16 维 EE（xyz + 四元数 + 夹爪） | **norm_stats 不通用**；与评测契约的对齐关系不同 |
| 旋转表示 | 关节角（无旋转表示问题） | 四元数（OpenDM EE 约定用轴角） | 用 B 训练 OpenDM 的 EE 通路需转换（四元数→rotvec） |
| 任务集合 | 34（缺 letters 任务） | 35 | 要 35 任务全集只能用 B |
| episodes 编号 | 每任务 0–99 | 全局（cover_blocks = 300–399） | 跨集对齐需按任务映射 |
| 存储格式 | JSONL + 每集小 mp4 | parquet + 分片 mp4 + meta | 读取路径、随机读粒度不同 |
| 视频编码 | h264 0.40 Mbps | av1 5.26 Mbps | 同内容体积差 ~7 倍（14 GB vs 112 GB） |
| 相机命名 | `images_1/2/3`（Head/Left wrist/Right wrist） | `observation.images.cam_high/...` | 转换时需映射键名 |
| 附带元数据 | 无 | 统计量、步索引、任务表、逐集元数据 | B 可直接算 norm_stats，A 依赖 checkpoint 或自算 |
| robot_type | ALOHA | `unified_robot` | 只影响 OpenDM 侧机型解析 |

## 5. 对训练 / 评测的实际含义

1. **要打 RoboDojo 榜单（XPolicyLab 契约），只能用 A（34 任务关节版）。**
   评测契约为 `arx_x5 / joint / 14 维绝对关节`（`XPolicyLab/policy/OpenDM/deploy.yml`、`action_type=joint`），B 的 16 维 EE 与榜单动作空间不一致。
2. **norm_stats 绝对不能跨用。** B 是 16 维、EE 物理量；A 是 14 维、关节角。官方推荐的统计量是 `DM05-MEM-Robodojo-Sim/norm_stats.json`（14 维关节，单档，无 `control_modes`）。
3. **存储/IO 差 ~7 倍。** 112 GB(av1) vs 15.8 GB(h264)：B 的近无损编码对磁盘与页缓存压力大得多；B 按 200 MB 分片、A 按每集 3 个小文件，训练取帧的随机读放大特性不同。
4. **要 35 任务全集（含 letters 任务）只能走 B**；A 侧 34 任务无对应项，本地 `*_joint_v30` 家族也没有它的关节版。
5. **两版互为交叉验证集。** 由于 episode/帧一一对应，适合做"同 rollout 的关节↔EE 一致性"检查，或做多动作表示联合训练。

## 6. 附带发现

### 6.1 本地 RoboDojo 家族：关节版与 EE 版成对存在

`/mnt/cfs/data/robodojo/`（=`/root/data/robodojo/`）下同名数据的两个导出，**帧数完全相同**（例：`make_kong` 195 eps / 70,121 帧，EE 与 joint 两版一致）：

| 数据集 | 任务 | eps | 帧数 | state 维度 |
| --- | ---: | ---: | ---: | ---: |
| `RoboDojo_ee_lerobot_v30_video` | 35 | 3500 | 1,859,602 | 16 (EE) |
| `RoboDojo_ee_cover_v30` | 1 | 100 | 54,396 | 16 (EE) |
| `RoboDojo_ee_fold_v30` | 1 | 100 | 30,351 | 16 (EE) |
| `RoboDojo_ee_2task_v30` / `_4task_v30` | 2 / 4 | 200 / 400 | 126,845 / 129,763 | 16 (EE) |
| `RoboDojo_gen_mcap100_6task_joint_v30` | 6 | 604 | 283,127 | **14 (joint)** |
| `RoboDojo_make_kong_joint_replay_v30` | 1 | 195 | 70,121 | **14 (joint)** |
| `RoboDojo_play_Xylophone_joint_v30` | 1 | 159 | 46,441 | **14 (joint)** |
| `RoboDojo_gen_*_align_v30` 系列 | 1–4 | 98–402 | — | 16 (EE) |

### 6.2 OpenDM 自带 EE 转换通路

- 注册：`opendm/dataset/robodojo_ee.py`（前缀 `robodojo_ee`，键 `cover`），`control_mode: "eef"`，state_desc 为 `EEF×6 + GRIPPER` 每臂。
- 转换脚本：`script/robodojo_lerobot_to_opendm.py`
  - 输入：LeRobot v3.0 的 `meta/ + data/ + videos/`
  - 变换：**16 维 `[pos3, quat(wxyz), grip] ×2` → 14 维 `[pos3, axis-angle(3), grip] ×2`**（四元数→旋转向量）
  - 产物：OpenDM JSONL；视频**直接引用分片 mp4 + 绝对 `frame_idx`**（不重编码）
- 现状：`data/robodojo_ee/` 只转换了 `cover` 一个任务（来源 `/mnt/cfs/data/robodojo/RoboDojo_ee_cover_v30`，manifest 记录 `source_state_dim=16 → output_dim=14`、100 集）。

### 6.3 一处死链

`opendm/dataset/robodojo_ee.py` 的 docstring 引用 `docs/zh/dm05_robodojo_ee.md`，**该文件不存在**（仓库内也没有其它 `robodojo_ee` 文档）。

## 7. 复现校验命令

> 前置：`/root/miniconda3/envs/opendm/bin/python`（有 pyarrow/pandas/PIL）；视频对比需要 `ffmpeg/ffprobe`。

```bash
# ① 两边的规模
pd() { /root/miniconda3/envs/opendm/bin/python "$@"; }
B=/root/data/robodojo/RoboDojo_ee_lerobot_v30_video
A=/mnt/cfs/opendm/datasets/robodojo_sim

pd -c "
import json; i=json.load(open('$B/meta/info.json'))
print('B:', i['total_tasks'],'tasks', i['total_episodes'],'eps', i['total_frames'],'frames', i['fps'],'fps')
"
find $A/jsonl -name 'episode_*.jsonl' | wc -l          # 3400
cat $A/jsonl/*/episode_*.jsonl | wc -l                 # 1793999

# ② 逐任务帧数配对（关键校验：应得到 34 对 + 1 个 B 独有任务）
pd - <<'PY'
import pandas as pd, pathlib
ep = pd.read_parquet('/root/data/robodojo/RoboDojo_ee_lerobot_v30_video/meta/episodes/chunk-000/file-000.parquet',
                     columns=['episode_index','tasks','length'])
ep['task'] = ep['tasks'].map(lambda x: x.item() if hasattr(x,'item') else str(x))
g = ep.groupby('task').agg(eps=('episode_index','count'), frames=('length','sum')).reset_index()
rows=[]
for d in sorted(pathlib.Path('/mnt/cfs/opendm/datasets/robodojo_sim/jsonl').iterdir()):
    if not d.is_dir(): continue
    fs=sorted(d.glob('episode_*.jsonl')); fr=0
    for f in fs:
        with open(f,'rb') as fh: fr+=fh.read().count(b'\n')
    rows.append({'open':d.name,'eps':len(fs),'frames':fr})
m = pd.DataFrame(rows).merge(g, on=['frames','eps'], how='outer', indicator=True)
print(m['_merge'].value_counts().to_string())
PY

# ③ 单帧语义（A：action[t]==state[t+1]；B：四元数模长 1.0、action[t]≈state[t+1]）
pd -c "
import json,numpy as np
r=[json.loads(l) for l in open('$A/jsonl/cover_blocks/episode_0000000.jsonl')]
st=np.array([x['state'] for x in r]); ac=np.array([x['action'] for x in r])
print('A: state',st.shape,'| max|action[:-1]-state[1:]| =', np.abs(ac[:-1]-st[1:]).max())
"

# ④ 同帧画面相关性（需 ffmpeg）：B 的 cover_blocks 首集在 cam_high 的 chunk-000/file-026.mp4，起始 62.880 s
ffmpeg -v error -ss 64.880 -i $B/videos/observation.images.cam_high/chunk-000/file-026.mp4 -frames:v 1 -y /tmp/b50.png
ffmpeg -v error -i $A/video/cover_blocks/episode_0000000/cam_head.mp4 -vf "select=eq(n\,50)" -frames:v 1 -y /tmp/a50.png
pd -c "
import numpy as np; from PIL import Image
a=np.asarray(Image.open('/tmp/b50.png').convert('RGB'),dtype=np.float32)
b=np.asarray(Image.open('/tmp/a50.png').convert('RGB'),dtype=np.float32)
print('相关系数', round(np.corrcoef(a.ravel(),b.ravel())[0,1],4), '平均绝对差', round(np.abs(a-b).mean(),2))
"
```
