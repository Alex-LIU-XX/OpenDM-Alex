## 0. 速查（TL;DR）

一句话：**DM05 = 一个 Gemma3-4B 多模态前缀编码器 + 一个 0.86B 的「动作专家」后缀解码器，两者共用同一套位置编码与注意力形状；每个动作 chunk 用 flow matching 训、用 10 步 Euler 采样推。**

| 你关心的 | 答案 |
| --- | --- |
| 结构 | Gemma3 VLM（0.41B 视觉塔 + 3.88B 文本塔[含绑定 embedding]）+ **0.86B** 动作专家 |
| 参数量（实测） | 张量 1473 个，**带重复计数 5.83B**；`lm_head` 与 `embed_tokens` 权重绑定 → **唯一参数 5.16B** |
| 输入 | 3 路当前 RGB（head/left-wrist/right-wrist，448×448）+ head 相机最多 20 帧历史（1 FPS）+ 一句任务 prompt + 14 维 state 的离散文本 |
| 前缀长度 | 实测 **1213 ~ 1243 token**（几乎不随历史条数变化，见 3.3） |
| 输出 | **14 维绝对关节，chunk 长度 50**（`action_dim` padding 到 32） |
| 一次推理的算力结构 | 前缀 VLM **只算 1 次**；动作专家跑 **10 次**（10 个扩散步），每次只处理 50 个 token |
| 关键设计 | 动作专家**不自己算前缀 K/V 的投影**，而是**直接复用 VLM 那 34 层写下的 K/V**，在每层里 concat 后一起做 attention |
| 时间条件 | AdaRMSNorm：`t` 经 sin-cos 编码 + 2 层 MLP，逐层生成 `(scale, shift, gate)` |
| 训练目标 | `x_t = t·noise + (1-t)·action`，回归速度场 `u_t = noise - action`，掩码 MSE |
| 榜单权重 | `DM05-MEM-Robodojo-Sim`：F32 存储 23.32 GB，架构与 BF16 基座 `DM05-MEM` 逐张量一致 |

## 1. 整体结构：不是 encoder–decoder，是「前缀 KV + 后缀层」

### 1.1 为什么不能简单叫 VLM + 小 head

多数 VLA（含 π0 系）的形态是：VLM 出一个条件向量/交叉注意力 KV，动作头是**另一个** attention 模块去 cross-attend。DM05 的做法更"咬合"：

```
             ┌──────────────── 前缀（prefix） ────────────────┐   ┌──── 后缀（suffix） ────┐
token 序列：  文本 + <unused1> 历史空槽 + <unused0> 历史槽 + 3×当前图(256 soft) + 文本
             └──────────── 34 层 Gemma3 text decoder ───────┘
                              │ 每层写下 K/V
                              ▼
                       prefix KV cache (34 层)
                              │ 直接当"自己的前半段"
                              ▼
             ┌──────────────── 50 个动作 token ───────────────┐
             │  x_t → action_in_proj → 1024 维                 │
             │  34 层 action expert（与上面同 head_dim/层数）  │
             └────────────────────────────────────────────────┘
                              │ action_out_proj
                              ▼
                         v_t（速度场，32 维）
```

关键点（`dm05_arch.py:250-385`）：动作专家的每一层从 `prefix_cache_keys[layer_idx]` / `prefix_cache_values[layer_idx]` 取出**同一个 layer_idx 的 VLM K/V**，与自己算出的 suffix K/V 在序列维 `cat` 起来，然后**一次普通的 self-attention**。

- 所以它**不是** cross-attention：Q 来自 suffix，K/V = `[VLM 的 K/V ; suffix 的 K/V]`。
- 所以它**必须**和 VLM 文本塔共享：层数、`head_dim`、`num_attention_heads`、`num_key_value_heads`、`layer_types`、RoPE 参数。`dm05_utils.py:109` 的 `validate_action_config_compatible()` 就是这条约束的守门员，构造期不一致直接报错。
- 所以 **VLM 前缀只前向一次**，10 个扩散步反复复用这份 KV —— 这是整个推理性能结构的根。

## 3. 输入侧：一条 JSONL 帧怎么变成 token

### 3.1 数据集注册与 transform 管线

RoboDojo 单任务注册在 `opendm/dataset/robodojo.py`：

```python
"sim_cover_blocks": {
    "jsonl_dir": "./data/robodojo_sim/jsonl/cover_blocks",
    "image_dir": "./data/robodojo_sim/video",
    "image_keys": ["images_1", "images_2", "images_3"],
    "image_prompts": ["Head", "Left wrist", "Right wrist"],
    "robot_type": RobotType.ALOHA,
    "state_desc": ROBOT_STATE_DESCS[RobotType.ALOHA],   # 14 维关节
    "fps": 25, "speed": "0.5",
}
```

playground 组装的管线（`playground/dm05_mem_sft_robodojo_cover_blocks.py`）：

```
BuildActionChunk(50)                     # 从 raw_lines 取未来 50 帧 action → [1,50,14]
LoadImages(3 视角 → 视频按 frame_idx 精确取帧)
LoadHistory(image_key=images_1, 1 FPS, 20 槽)   # 只回看 head 相机
Normalize(norm_stats.json, use_quantiles=True)  # state/action 归一化到 ~[-1,1]
ChatTokenization(..., is_history=True, max_history_images=20)
PadAction(32)                            # 动作最后一维 pad 到 32，action_mask 同步
TrainingCollator(max_length=1536)        # 右侧 pad
```

`JsonlDataset._build_index()` 会为每个 jsonl 文件取 `max(0, 行数-1)` 个样本（最后一帧没有未来动作，丢弃），首次运行生成 `index_cache.json`。`cover_blocks` 实测 **54,296 个训练样本**。

### 3.2 一条真实样本（实测）

```
--- sample idx=0 frame=0 ---
  action    (1, 50, 32)  mask (1, 50, 32)
  input_ids (1, 1213)    pixel (3, 3, 448, 448)
  hist px   None         hist mask 0      visible prefix 893
--- sample idx=400 frame=400 ---
  input_ids (1, 1232)    pixel (3, 3, 448, 448)
  hist px   (16, 3, 448, 448)  hist mask 256   visible prefix 1168
--- sample idx=1000 frame=445 ---
  input_ids (1, 1234)    pixel (3, 3, 448, 448)
  hist px   (17, 3, 448, 448)  hist mask 272   visible prefix 1186
```

注意 `hist mask` 恰好是 `16 × 历史图数`——每个历史图占 **16 个占位 token**。

### 3.3 prompt 组装与真实 token 布局（用官方 tokenizer 实渲染）

`ChatTokenization.__call__`（`transforms.py:716`）拼出的 user 内容：

```text
Robot: Aloha
Overall speed: 0.5
Task: Cover the blocks from left to right, remember their colors, then uncover them
      in the order: red, green, and blue..
History images: <unused1>×272 <unused0>×16 ⏎ <unused0>×16 ⏎ <unused0>×16 ⏎
Head image:        <start_of_image> <image_soft_token>×256 <end_of_image>
Left wrist image:  <start_of_image> <image_soft_token>×256 <end_of_image>
Right wrist image: <start_of_image> <image_soft_token>×256 <end_of_image>
States: 127 127 127 127 127 127 127 127 127 127 127 127 127 127
```

（`... and blue..` 的两个句点是真实的：JSONL 里的 `prompt` 自带句点，模板又追加一个 `.\n`。state 是归一化后分 256 桶的整数，0 归一化后落在第 127 桶。）

实测 token 计数（20 个历史槽）：

| 历史图数 | 总长 | `<unused0>` | `<unused1>` | `<image_soft_token>` |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 1223 | 0 | 320 | 768 |
| 3 | 1226 | 48 | 272 | 768 |
| 20 | 1243 | 320 | 0 | 768 |

**读法**：20 个槽的"槽位payload"恒为 `20×16 = 320` 个 token；空槽是 `<unused1>`（id **7**），有效槽是 `<unused0>`（id **6**）。每填进一张真实历史图，就有一个 `<unused0>×16` 换掉 `<unused1>×16` 并多一个换行 → 净增 1 token。所以**前缀长度基本恒定**（1223→1243），这一点对 CUDA Graph / 静态 bucket 很重要。

其它实测事实：

- 空槽在**左边**（`<unused1>` 全部出现在有效槽之前）→ 就是官方说的"episode 开头的空槽左侧 padding"。
- `history_mask` 标的是 `<unused0>` 的位置；`ChatTokenization` 还会把这些位置的 `token_type_ids` 置 1（对齐 dexbotic 的"历史槽也算图像 token"）。
- `<image_soft_token>`（262144）由 chat template 生成，`<unused0>`(6) / `<unused1>`(7) 是 Gemma 词表里的保留位——**它们不产生任何视觉计算，只是"占位插座"**，真正的历史特征在模型内部 `masked_scatter` 进去（第 4.2 节）。
- 当前三视图：3×(1 `start_of_image` + 256 soft + 1 `end_of_image`) = **774**；基础文本+模板 ≈ 129（含 `BOS`/`<start_of_turn>`/角色名/换行）。

### 3.4 历史槽是怎么采样的

`LoadHistory`（`transforms.py:229`）：以当前帧为基准，槽 `slot = max_history_images … 1`，取

```python
raw_index = frame_index - round(slot / 1.0 * source_fps)   # source_fps=25
```

即"**1 FPS 均匀回看**"：第 1 槽回看 25 帧（1 秒前），第 20 槽回看 500 帧（20 秒前）。越界的槽直接丢弃 → 得到的就是**紧凑的有效列表**（旧的在前），再由 `ChatTokenization` 补到 20 槽并用 `<unused1>` 左填充。第 3.2 节的实测正是这个规律：frame 400/445 分别有 16/17 张有效历史。

> `LoadHistory` 只读 `image_keys[0]`（head 相机）。RoboDojo 官方部署口径也是"最多 20 帧 head 历史"。

### 3.5 动作侧的归一化

`Normalize` 用 **quantile 归一化**（`use_quantiles=True`，`transforms.py:137`）：

```python
x_norm = (x - q01) / (q99 - q01 + 1e-6) * 2 - 1        # 到 ~[-1,1]
# (lo==0 且 hi==0 的维度直接置 0)
```

`clip_to_bounds=True` 时先把 `x` 夹到 `[q01,q99]`；RoboDojo 入口用 `clip_to_bounds=False`（只线性映射，不夹断）。`norm_stats.json` 必须与训练同源；RoboDojo 榜单权重自带一份（`/mnt/cfs/opendm/checkpoints/DM05-MEM-Robodojo-Sim/norm_stats.json`，14 维 state/action 各一套 `mean/q01/q99/std`）。

推理出动作后的逆运算由 `output_transform` 里的 `Denormalize` 完成（`dm05_exp.py:627/688`，**不是** `Normalize`）：

```python
x = (x_norm + 1.0) / 2.0 * (q99 - q01 + 1e-6) + q01     # quantile 路径
x = x_norm * (std + 1e-6) + mean                        # mean/std 路径（本场景不走）
```

## 4. 前缀前向：`_compute_prefix_cache()` 逐行

入口 `dm05_arch.py:1423`。它做的事：**把整条前缀喂进 Gemma3，把 34 层的 K/V 留下来，并返回前缀长度。**

### 4.1 分叉：有没有历史

```python
has_history_pixels = history_pixel_values is not None and history_mask.any()
has_history_pads   = (input_ids == 7).any()          # <unused1>
if has_history_pixels or has_history_pads:
    # 手搓 inputs_embeds
else:
    # 完全走 HF 原生路径：input_ids + pixel_values
```

RoboDojo 只要开了 `is_history=True`，**必然走手搓分支**：20 个槽要么是有效历史（`has_history_pixels`），要么是 `<unused1>` 空槽（`has_history_pads`），二者必居其一。

### 4.2 历史注入（唯一"非标准"的地方）

```python
inputs_embeds = embed_tokens(input_ids)
inputs_embeds[input_ids == HISTORY_PAD_TOKEN_ID] = 0        # <unused1> 位置清零

image_features = vlm_model.get_image_features(history_pixels).pooler_output
#   [n_hist, 256, 2560]  ← 视觉塔 + 多模态投影，已是 LLM 隐空间
grid  = image_features.view(-1, 16, 16, 2560).permute(0,3,1,2)
grid  = F.adaptive_avg_pool2d(grid, (4, 4))                 # 16×16 → 4×4
image_features = grid.reshape(-1, 16, 2560)                 # 每图 16 token

prefix_inputs_embeds = inputs_embeds.masked_scatter(
    history_mask.unsqueeze(-1).expand_as(inputs_embeds), image_features)
```

三件事值得记住：

1. **历史图不做"每图 256 token"**，只在 LLM 空间降到 **16 token/图**（4×4 池化）。20 张历史一共 320 token。
2. 历史图**没有"每图一段软 token 再单独编码"这一步**：视觉塔 + 多模态投影出来的 256 个特征被池化到 16 个，**直接作为序列里 `<unused0>` 那 16 个位置的输入 embedding**，和前缀其它 token 一起进 34 层。历史与当前画面的"融合"就发生在那 34 层 self-attention 里（代价是每张历史图只剩 16 个 token 的信息量）。
3. `<unused1>` 的 embedding 被显式清零，且在第 4.4 节会被注意力屏蔽掉——**双保险**，保证空槽不产生任何影响。

### 4.3 当前三视图

`pixel_values`（`[3,3,448,448]`）和 `token_type_ids` 原样传给 `self.model.vlm.model(...)`，由 HF 的 `Gemma3Model.forward` 内部完成：

```python
image_features = self.get_image_features(pixel_values).pooler_output  # [3,256,2560]
special_image_mask = input_ids == image_token_id                       # 262144
inputs_embeds = inputs_embeds.masked_scatter(special_image_mask, image_features)
```

所以当前图走的是**标准 Gemma3 多模态路径**（256 token/图），历史图走的是**自定义 16 token 路径**——两条路在同一个 `inputs_embeds` 上汇合。两处 `masked_scatter` 的掩码互不重叠（6 vs 262144），先后顺序无所谓。

> 副作用：历史分支下视觉塔会被调用**两次**（一次历史批、一次当前批）；`infer` 的 fast 路径改成"一个 TRT 引擎一次吃掉 current+history 全部图"，见第 7.3 节。

### 4.4 注意力掩码与位置编码

```python
prefix_attention_mask = mask_history_pad_tokens_in_attention(input_ids, attention_mask)
#   → 把所有 <unused1>(7) 位置置 0（不可见）
prefix_position_ids = (prefix_attention_mask.cumsum(-1) - 1).clamp_min_(0)
```

- `<unused1>` 被 mask 掉 → 别人看不到它；
- 它的 `position_id` 因为 cumsum 不推进 → **和它前一个可见 token 共用位置号**；
- `<unused0>`（历史槽）**不**被 mask，正常参与，位置号正常推进。

`token_type_ids` 还会触发 Gemma3 的 `token_type_ids_mask_function`：同一图像块内的 token 之间是**双向注意力**（image block 内不 causal），这是 Gemma3 原生的多模态行为，DM05 沿用。

### 4.5 KV cache 与长度

```python
kv_cache = cache_cls(config=self.model.language_model.config)
prefix_outputs = self.model.vlm.model(**model_kwargs)   # use_cache=True
return kv_cache, prefix_outputs.last_hidden_state
```

- 训练时 `cache_cls=VLADynamicCache`，推理时 `cache_cls=DynamicCache`。
- `VLADynamicCache` 里的 `OverwriteDynamicLayer.update()` 直接 `self.keys = key_states`（**覆盖式赋值**，不是拼接到无梯度 buffer），目的是**保留 autograd 图**：动作专家的 loss 要能反传到 VLM 的 K/V 投影权重。同时它也让"梯度检查点重算时重复写入"变得幂等（配合 `patch_decoder_layers` 生成的 `SafeCacheDecoderLayer`）。
- 前缀长度 `prefix_len = prefix_hidden_states.shape[1]`：
  - **训练**经过 `TrainingCollator` 右侧 pad，恒为 `max_length=1536`；
  - **推理服务**不过 collator，就是 `ChatTokenization` 的原始长度，即第 3.3 节实测的 **1213~1243**（fast 路径再按 bucket 补齐到 2048 的静态 buffer，pad 位不参与注意力）。

> 训练时 `last_hidden_state` 本身**不进 loss**（只有 FP32 策略下会 `+ prefix_hidden_states.sum()*0.0` 这一手，用来给 FSDP 包裹的模块喂一条反向通路）。**VLM 的梯度完全来自动作专家对 prefix KV 的使用。**

## 5. 后缀前向：`DM05ActionExpert` 逐层

入口 `_suffix_forward_layers`（`dm05_arch.py:250`），34 层循环 + 一次最终 AdaRMSNorm。

### 5.1 每个扩散步的输入准备

```python
suffix_embeds = self._action_input_proj(x_t)       # [B,50,32] → [B,50,1024]
adarms_cond   = self._build_adarms_cond(time)      # [B,1024] 时间条件
```

`_build_adarms_cond`：`posemb_sincos(t, 1024, max_period=4.0)` → `time_mlp_in` → SiLU → `time_mlp_out` → SiLU。

`posemb_sincos` 的周期范围是 `min_period=4e-3, max_period=4.0`（注意 `max_period` 在调用点被显式设成 **4.0**，不是默认的 256）。

### 5.2 单层计算图（`_compute_suffix_layer`）

```
prenorm, attn_gate = adaRMSNorm(input_layernorm.eps, h, input_time_modulators[i])
        │  h·rsqrt(mean(h²)+eps)·(1+scale) + shift
        ▼
q,k,v = q_proj/k_proj/v_proj(prenorm)        # 1024 → 8×256 / 4×256 / 4×256
q,k   = q_norm(q), k_norm(k)                 # 对 head_dim=256 做 RMSNorm
q,k   = RoPE(q, k, position_ids, layer_type) # layer_type ∈ {sliding, full}
        ▼
K_full = cat([prefix_cache_keys[i], k], dim=seq)     # ★ 复用 VLM 的 K
V_full = cat([prefix_cache_values[i], v], dim=seq)
        ▼
attn  = attention(q, K_full, V_full, suffix_attn_mask)   # eager / sdpa / flex
        ▼
attn_embeds = post_attention_layernorm(o_proj(attn))     # 学习权重 (1+w) 照常生效
residual    = h + attn_embeds * attn_gate                # ★ gate 门控残差
        ▼
mlp_input, mlp_gate = adaRMSNorm(pre_feedforward_layernorm.eps, residual, mlp_time_modulators[i])
mlp_out = post_feedforward_layernorm(mlp(mlp_input))     # Gemma3 GeGLU MLP
        ▼
h_out = residual + mlp_out * mlp_gate
```

最后：

```python
h = adaRMSNorm(final_norm.eps, h, final_time_modulator)  # 不做 gate，只用 scale/shift
v_t = self._action_output_proj(h)                        # [B,50,1024] → [B,50,32]
```

**四个容易看漏的细节：**

| 细节 | 说明 |
| --- | --- |
| **AdaRMSNorm 取代了预归一化的学习权重** | `_adaptive_rmsnorm` 只用 `norm.eps`，`input_layernorm.weight` / `pre_feedforward_layernorm.weight` / 最终 `norm.weight` 这三类权重**在前向里不参与计算**（时间条件生成的 scale/shift 顶替了它们）。后归一化两处仍用 `(1+w)` 学习权重，和 Gemma3 一致。eager 与 Triton 快速路径**行为一致**（`dm05_bigkernel.py:375` 的 `_input_adarmsnorm_kernel` 同样只吃 eps + modulation）。 |
| **残差是门控的** | Gemma3 原生是 `h + norm(attn)`；这里是 `h + norm(attn) * gate`，gate 由时间条件逐通道生成。 |
| **后缀内部双向注意力** | `make_suffix_attn_mask` 的 suffix 块是**全零**（无 causal），50 个动作 token 互相全可见；对前缀则按 4.4 的可见性 mask。这也解释了为什么 50 步 chunk 能一次性出。 |
| **后缀 K/V 不写回 cache** | `cat` 只发生在局部变量里，每个扩散步都从零算这 50 个 token。前缀 KV 是唯一被复用的东西。 |

### 5.3 位置编码的衔接

```python
# _build_suffix_position_ids
valid_prefix = (input_ids[:, :prefix_len] != pad_token_id)          # 去掉右侧 padding
for tid in invisible_prefix_token_ids:                              # 再扣掉 <unused1>(7)
    valid_prefix &= (input_ids[:, :prefix_len] != tid)
effective_prefix_len = valid_prefix.sum(1)                          # [B]
suffix_pos = effective_prefix_len[:, None] + arange(suffix_len)[None, :]
```

动作 token 的位置号**紧接着最后一个"可见"前缀 token**（padding 和 `<unused1>` 都不计数）。因为 VLM 与动作专家共享同一套 RoPE 参数，前缀 K/V 和后缀 Q/K 处在**同一个旋转坐标系**里——这是"直接 cat 就能算"的前提。

拼接后 KV 长度若与 mask 长度不一致（prefix 长度对不上时会发生），`_compute_suffix_layer` 会自动右对齐截取：`attention_mask[..., -key_states.shape[-2]:]`。

### 5.4 三种后缀 attention 后端

`set_action_attention_backend()`：`eager` / `sdpa` / `flex_attention`（**没有 FA2**）。
- `_sdpa_attention` 手动 `repeat_kv` 后调 `F.scaled_dot_product_attention`，并传 **bool mask**（`mask==0` 即屏蔽），`scale=layer.self_attn.scaling`。
- `_flex_attention` 转发给 transformers 的 `flex_attention_forward`。
- 选型与实测见 [`../训练/注意力后端说明.md`](../训练/注意力后端说明.md)。

## 6. 训练前向：`DM05ForConditionalGeneration.forward()`

```python
# Step 1  前缀：算一次，拿 KV
kv_cache, prefix_hidden = self._compute_prefix_cache(..., cache_cls=VLADynamicCache)

# Step 2  构造 flow-matching 的 (x_t, t, u_t)
noise = torch.randn_like(action)
time  = Beta(1.5, 1.0).sample((B,)) * 0.999 + 0.001
x_t = time[:,None,None] * noise + (1 - time[:,None,None]) * action
x_t = x_t * action_mask
u_t = noise - action                       # 目标速度场

# Step 3  后缀：跑 34 层动作专家
suffix_out = self._suffix_forward(action_in_proj(x_t), mask, pos, kv_cache, adarms_cond(time))
v_t = action_out_proj(suffix_out)

# Step 4  掩码 MSE
per_sample = (mse(v_t, u_t) * action_mask).sum((1,2)) / action_mask.sum((1,2))
loss = per_sample.mean()
```

**约定**：`t=1` 是纯噪声、`t=0` 是干净动作；`u_t = d x_t / d t = noise - action`。推理时因此从 `t=1` 沿 `dt = -1/N` 往下积分。

**时间采样**：`Beta(1.5, 1.0)` 的密度 ∝ `t^0.5`（在 `[0,1]` 上单调递增，均值 0.6），再线性映射到 `[0.001, 1.0]` —— 即**偏向 t 较大的"高噪声端"多训一点**，而不是偏向干净动作端。

**掩码**：`action_mask` 是 `[B,50,32]` 的 0/1（`PadAction(32)` 之后真实 14 维为 1、padding 18 维为 0）。分子分母都被它加权，所以 padding 维既不贡献 loss 也不摊薄 loss。推理时 `dm05_exp.py` 也会按 `output_action_dim` 构造同样的 mask。

**其它训练期机制**（都在 `dm05_arch.py`）：

| 机制 | 位置 | 说明 |
| --- | --- | --- |
| 精度策略 | `set_precision_policy` | `bf16_mixed`（默认）或 `fp32_mixed`；后者下 `action_in/out_proj`、`time_mlp`、AdaRMS 调制走 `linear_fp32` + `torch.autocast(enabled=False)`，全局 TF32 关闭（`constants/precision.py`） |
| FSDP 切分 | `fsdp_wrap_modules()` | 固定切 `action_expert` + **VLM 最后 24 层**（`_FSDP_VLM_LAYERS_TO_WRAP=24`），不是任意自动切 |
| 梯度检查点 | `enable_gradient_checkpointing` | VLM 文本塔 + 视觉塔 + 动作专家分别开关；配合 `SafeCacheDecoderLayer` 保证重算时 KV 仍写入 |
| Liger Kernel | `_apply_liger_kernel` | VLM：RMSNorm+GeGLU+RoPE+SigLIP LayerNorm；AE：只 RMSNorm+GeGLU（RoPE 由后缀路径自己管） |
| 冻结 embedding | `freeze_vlm_embedding()` | 冻结 `embed_tokens`，因权重绑定，`lm_head` 一起冻结 |
| LoRA | `dm05_lora.py` | `all-linear` + 必须 `modules_to_save` 投影与时间调制层，否则推理形状对不上 |

## 7. 推理前向：`inference_action()`

### 7.1 主循环（`dm05_arch.py:981`）

```python
kv_cache, prefix_hidden = self._compute_prefix_cache(..., cache_cls=DynamicCache)  # ← 只算一次
prefix_len = prefix_hidden.shape[1]

x_t = torch.randn(B, chunk_size, action_dim)        # t = 1，纯噪声
time_val, dt = 1.0, -1.0 / diffusion_steps
for _ in range(diffusion_steps):                    # 默认 10 步
    x_t = x_t * action_mask                          # padding 维恒为 0
    suffix_embeds = action_in_proj(x_t)
    adarms_cond   = build_adarms_cond(time_val)
    suffix_out    = suffix_forward(...)              # 复用同一份 prefix KV
    x_t = x_t + action_out_proj(suffix_out) * dt     # 欧拉步
    time_val += dt
return x_t                                           # [B, 50, 32]
```

**一次请求的算力账**：前缀（约 1230 token × 34 层，含视觉塔）**1 次**；后缀（50 token × 34 层）**10 次**。所以前缀占了绝大部分 FLOPs，也是为什么"前缀只算一次 + 缓存 KV"是核心优化点。

`diffusion_steps` 在服务里是**固定值**（`dm05_exp.py:938` 会拒绝运行时改步数）——因为 CUDA Graph 是按固定步数捕获的。

### 7.2 CUDA Graph（`_run_suffix_graph`）

- 触发条件：`not training and x_t.is_cuda and 后缀后端 == "sdpa"`；
- 粒度：**每次 `inference_action` 捕获"10 个扩散步"整段**（graph 内部循环由 host 端 `graph.replay()` ×10 驱动，`time` 用静态 buffer `fill_()` 改写）；
- 前缀长度按 **16 对齐分桶**（`_SUFFIX_GRAPH_PREFIX_BUCKET_ALIGNMENT=16`），KV cache 复制进固定 shape 的静态张量；
- LRU 缓存 8 个 profile；每个 key 需要连续命中两次才捕获（`_should_capture_suffix_graph_profile`），失败则永久禁用该 key 并回退 eager；
- `input_ids`/`action_mask`/`prefix KV` 每次 replay 前 `copy_` 进静态 buffer。

### 7.3 服务端 fast 路径（`DM05FastInferRuntime`）

`--inference-config.backend fast` 时走另一套（`dm05_infer.py` / `dm05_infer_arch.py`）：

1. **视觉走 TensorRT**：`build_vision_trt.py` 离线编译引擎；开历史时引擎输入是 `num_current + max_history` 张图**一次性**前向，再切分成 current / history 两段（历史段做 4×4 池化）。这就消掉了第 4.3 节说的"视觉塔跑两次"。
2. **前缀按 bucket 预捕获**：默认 `DEFAULT_PREFIX_SEQ_LEN_BUCKETS=(576,704,768,896,1024)`（RoboDojo 入口覆盖成 `[2048]`），启动时对每个 bucket 捕获一张"前缀 + 后缀全流程"的 CUDA Graph。
3. **无历史请求**：直接 replay bucket graph（最快路径）。
4. **有历史请求**：跳过捕获（历史条数每次都可能不同），走 `prefill_fast_from_image_features` + `decode`，但仍用 Triton bigkernel（`dm05_bigkernel.py`）跑融合算子。
5. **超过最大 bucket**：退化为 `_run_dynamic_without_capture`（eager），并打一条 warning、计数 `dynamic_fallback_count`。

fast 路径的前缀必须是 **batch=1**、长度 ≤ `prefix_len`（RoboDojo 入口 2048）。

### 7.4 出参处理

`dm05_exp.py` 的 `_predict` 拿回 `[1,50,32]` 后：

```python
raw = actions[0, :, :output_action_dim]     # 取前 14 维
# → output_transform = Pipeline([Denormalize(use_quantiles=True), (ActionAbsolute)])
#   先反归一化回关节量纲，再按 action_mode 做相对/绝对还原（RoboDojo 用 absolute，且不 compose_eef_rot）
```

RoboDojo 评测适配器**只执行每个 chunk 的前 25 步**（官方口径），仓库内推理服务返回 50 步由客户端截断。

## 10. 易错点 / 常见误解

| # | 说法 | 实际 |
| --- | --- | --- |
| 1 | "动作专家是 cross-attention 到 VLM" | ❌ 是**同层 K/V 拼接后的 self-attention**；因此两者 `head_dim`/层数/`layer_types` 必须严格一致，改一个必须改另一个 |
| 2 | "`action_dim=32` 就是 32 维动作" | ❌ RoboDojo 真实动作 **14 维**，32 是统一 padding 宽度；多出来的 18 维由 `action_mask` 屏蔽 |
| 3 | "历史图也是 256 token/图" | ❌ 历史图被 4×4 池化成 **16 token/图**；256 token/图只用于当前 3 视图 |
| 4 | "历史越多 prompt 越长，graph 越难抓" | ⚠️ 前缀长度只从 1223 漂到 1243（空槽也是 16 token），**长度几乎不变**；真正随历史变的是 `history_pixel_values` 的**张量形状**，所以 fast 路径仍按"有无历史"分成两条 |
| 5 | "`<unused0>`/`<unused1>` 是图像 token" | ⚠️ 它们是**占位符**。渲染时只占位、不触发视觉计算；真正的历史特征在模型内部 `masked_scatter` 注入。`<unused1>` 还会被清零 + mask 双重屏蔽 |
| 6 | "AdaRMSNorm 就是 Gemma3 的 RMSNorm" | ❌ 预归一化位置**不用**学习权重 `w`，改用时间条件生成的 `(1+scale, shift)`；`(1+w)` 只保留在后归一化两处 |
| 7 | "动作专家自己的 K/V 会缓存" | ❌ 每个扩散步重算 50 个 token；被缓存的只有 VLM 前缀 KV |
| 8 | "推理步数可以随手调" | ❌ 服务里 `diffusion_steps` 固定（默认 10），CUDA Graph 按固定步数捕获；传别的值直接报错 |
| 9 | "训练时 VLM 靠 LM loss 学" | ❌ DM05 的 loss **只有 flow-matching 一项**，VLM 的梯度全部来自动作专家对 prefix KV 的依赖（FP32 策略下靠 `sum()*0.0` 补一条 FSDP 通路） |
| 10 | "F32 的榜单权重是另一个模型" | ❌ 与 BF16 的 `DM05-MEM` **1473 张量逐一对应**，只是 `dtype` 存成 `float32`（体积翻倍） |
